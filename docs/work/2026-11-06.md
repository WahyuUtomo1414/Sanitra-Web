# Work Log — 6 November 2026

## Insiden besar: server E2E "isolated" ternyata punya 4 bug tersembunyi bertumpuk

User melaporkan "banyak yang merah" saat testing manual (`npm run test:e2e:ui`) terhadap infra E2E yang ditambahkan sesi sebelumnya (10 spec resource master + server isolated SQLite di `tests/e2e/start-server.sh`, port 8011). Investigasi mendalam menemukan **4 bug tersembunyi yang bertumpuk** di `start-server.sh` — bukan 1 masalah, melainkan rangkaian masalah yang masing-masing menutupi yang lain:

### 1. Config cache basi → insert nembus ke MySQL asli (paling serius)

`bootstrap/cache/config.php` (dibuat sebelumnya, di luar sesi ini) membuat Laravel mengabaikan override `DB_CONNECTION=sqlite` dari script, sehingga request HTTP (via Livewire form submit) benar-benar nulis ke **MySQL `sanitra` lokal asli** — persis pola insiden yang diperingatkan `docs/testing-safety.md`. Terdeteksi dari log: `Connection: mysql, Database: sanitra` pada error "Duplicate entry '1-99'" saat test Workflow Project gagal berulang.

**Dampak:** beberapa record uji coba (`name LIKE 'E2E%'`) sempat kebentuk di MySQL asli sebelum collision. **Sudah dibersihkan manual** — audit menyeluruh ke `MsUnit`, `MsItemCategory`, `MsItem` (+ `ms_item_unit`), `MsClient` (+ `ms_client_contact`, `ms_document`), `MsCompany`, `MsEmployee`, `MsBankAccount`, `MsProjectType`, `MsProjectWorkflow` — semua kembali 0.

**Fix:** `rm -f bootstrap/cache/config.php` di awal `start-server.sh` (defense-in-depth; `APP_CONFIG_CACHE` override per-run sudah mencegah script sendiri kena, tapi file basi ini sebaiknya tidak dibiarkan ada sama sekali untuk siapa pun yang share checkout ini).

### 2. `php artisan serve` tanpa `--no-reload` men-strip SEMUA custom env var

Root cause asli dari #1 di level infra: Laravel `ServeCommand::startProcess()` (lihat `vendor/laravel/framework/.../ServeCommand.php`) hanya meneruskan **allowlist env var** (`APP_ENV`, `PATH`, dll — TIDAK termasuk `DB_CONNECTION`/`DB_DATABASE`/`APP_LOCALE`) ke proses yang benar-benar menangani HTTP request, KECUALI flag `--no-reload` dipakai. Dikonfirmasi via `ps eww -p <pid>`: proses server beneran cuma punya `APP_ENV=testing` di environment-nya, bukan var lain yang di-`export` di script. Server lantas fallback ke `.env.testing` (`DB_DATABASE=:memory:` — kosong, tak pernah di-migrate) untuk SEMUA request, terpisah total dari file SQLite yang sudah di-migrate+seed oleh CLI command di baris sebelumnya di script yang sama.

**Fix:** tambah `--no-reload` ke `php artisan serve`.

### 3. `RoleSeeder` butuh `shield:generate` dulu — super_admin kelihatan "tidak berhak create"

`RoleSeeder` men-sync `super_admin` ke **permission yang sudah ada sebagai row** di DB (`Permission::query()->where('guard_name','web')->get()`), bukan generate permission baru. Permission seperti `Create:MsBankAccount`/`Create:MsUnit` cuma ada di app asli karena `shield:generate` pernah dijalankan historically (lihat urutan deploy di `docs/work/2026-10-31.md`). Di SQLite fresh, baru ada permission yang eksplisit disebut `RoleSeeder::ROLE_PERMISSIONS` (Marketing/Finance/Teknis) — resource yang tidak disebut di situ (`MsBankAccount`, `MsUnit`, `MsProjectWorkflow`, dll) jadi **tidak punya permission Create/Update/Delete sama sekali**, sehingga super_admin pun tidak kebagian walau seharusnya full access.

**Fix:** jalankan `php artisan shield:generate --all --option=permissions --panel=dashboard --no-interaction` sebelum `db:seed`.

### 4. Upload file gagal 500 — Livewire hardcode disk `tmp-for-tests` saat `APP_ENV=testing`

`vendor/livewire/livewire/src/Features/SupportFileUploads/FileUploadConfiguration.php::disk()` return `'tmp-for-tests'` setiap kali `app()->runningUnitTests()` true — yang dipicu murni oleh `APP_ENV=testing`, bukan berarti benar-benar jalan di PHPUnit. Disk itu biasanya di-`Storage::fake()` otomatis oleh PHPUnit TestCase; server E2E kita (`php artisan serve` beneran, bukan PHPUnit) tidak pernah fake disk itu → error "Disk [tmp-for-tests] does not have a configured driver." setiap upload file (ditemukan di test `ms-client.spec.ts` — upload dokumen klien).

**Fix:** daftarkan disk `tmp-for-tests` di `config/filesystems.php` (pola resmi yang direkomendasikan Livewire sendiri untuk kasus ini — harmless untuk app asli).

### Bug tambahan (bukan infra, tapi ikut ketemu & di-fix saat audit)

- **Rate limiter login numpuk lintas-run** — `CACHE_STORE=file` di script lama nulis ke `storage/framework/cache` yang SAMA dengan app asli, jadi hit rate limiter dari berbagai run (manual + otomatis) saling akumulasi. Fix: `CACHE_STORE=array` (in-memory per-proses, benar-benar isolated).
- **Race condition submit sebelum Select selesai diproses** (`Workflow Project` create) — tombol "Buat" sempat `disabled` saat Livewire proses pilihan `Tipe Project` (searchable select), klik terlalu cepat. Fix: `await expect(createButton).toBeEnabled()` sebelum klik, diterapkan generik di `master-resource.ts`.
- **Race condition submit sebelum upload file selesai** (`ms-client.spec.ts`, dokumen klien) — `setInputFiles()` memicu upload async, klik submit langsung sesudahnya race dan gagal validasi "The file field is required." Fix: tunggu teks "Pengunggahan selesai" (`.first()`, karena teksnya duplikat di DOM — status utama + assistive text) sebelum klik submit.
- **Selector "Email" ambigu** (`ms-client.spec.ts`, form kontak klien) — `getByRole('textbox', {name:'Email'})` match 2 field (field utama klien "Email Umum*" di background + field modal "Email"). Fix: `exact: true`.

## Pelajaran untuk sesi berikutnya

Jangan percaya "test infra sudah dibuat" = "test infra sudah benar jalan" tanpa verifikasi langsung — kerjaan sesi sebelumnya (10 spec + server isolated) sudah tertulis rapi tapi **belum pernah benar-benar dijalankan sampai hijau** (lihat `docs/work/2026-11-05.md`: "run ulang browser... belum dilakukan karena permintaan izin eksekusi terakhir ditolak"). Begitu benar-benar dijalankan, 4 bug tersembunyi langsung ketahuan. Prinsip yang dipakai untuk membongkar semua ini: jangan percaya status "passed/failed" superfisial, selalu `ps eww -p <pid>` untuk cek env var proses beneran, cek `storage/logs/laravel.log` untuk connection yang benar-benar dipakai, dan buat test probe sengaja gagal untuk dump accessibility snapshot halaman asli kalau tidak yakin behavior UI.

**Belum dikerjakan:** resource transaksi (`TransSalesQuotationHd`, `TransSalesOrderHd`, `TransSalesInvoiceHd`, `TransSalesPayment`) dan business flow test — lihat roadmap `docs/testing/playwright-strategy.md` §2.3–2.4.
